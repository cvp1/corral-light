### T-IMG-4 detail

`docker save | container/scan_layers.py` over all 14 layers. No credential, no
working host path, no host config in any layer. Hits, classified:

- **Vendor binaries / libraries** (string literals, not secrets): PEM
  `PRIVATE KEY` headers in openssh, gnutls, libssh2, jose, the Claude binary;
  token-shaped strings in the Codex binary, node, libunistring, and the
  Antigravity helper (an `AIza…` key Google ships in its own binary).
- **Fixtures**: `sk-abcdefghijklmnopqrstuvwxyz…` in Seed's
  `memory-mesh/test_learn_harvest.py`.
- **First-party identifiers in comments, license and labels** — the real
  finding: `mac-host` in comments across ten source files, `com.cvp1.*`
  launchd label and a `/home/USER/...` comment, `craigvandeputte` in both
  LICENSE files and a Seed comment. All are already public in the source
  repos, so the image adds no new exposure, but the plan's "no hostnames or
  usernames in any layer" is not literally met. The operator's call: scrub the
  comments (touches files the stop-and-clear branch also edits — do it after
  that merges) or accept and allowlist.

## Build storage on mac-host

The system disk ran low (9.5 GiB free): Docker Desktop's VM disk had grown
with 21 GB of build cache. Build work now lives on the Data volume under
`/Volumes/Data/Omachi/corral-build/` — `cache/` (BuildKit layer cache via
`CORRAL_BUILD_DIR`), `images/` (exported image tarballs), `p0a/` (compose
file, logs, the AI-OS copy). `build.sh` trims Docker's own cache to 2 GB
after each build. System disk after the move: 30 GiB free. Docker's disk
image itself was NOT moved: that needs a Docker Desktop restart, which would
interrupt Wavelog (wavelog-main, wavelog-db).

## Learned

- Docker Desktop's containerd store rejects `rewrite-timestamp` together with
  `unpack`; build.sh exports `type=image,unpack=false` and the image unpacks
  on first run.
- Claude Code and Codex Linux binaries need no separate download: `npm ci`
  from the lockfile installs the x64 platform packages with sha512 integrity.
- Grok publishes no checksum (its install.sh only runs `--version`); pinned
  from first download, like Antigravity.
- Grok has a device-flow login (`GROK_LOGIN_DEVICE_FLOW`) — the likely
  container login path for WS6.
- SSH agent forwarding (`/run/host-services/ssh-auth.sock`) not present:
  Docker Desktop's setting is off or the socket was not mounted. P0b.
