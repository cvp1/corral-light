# Proposal — one portable install for Corral Light (container-first)

Status: **v1 FINAL FOR PANEL REVIEW**, 2026-10-01. Nothing built.
Author: Claude (the Mac host session) for the operator, who owns the system and decides.
History: v0 drafted 2026-10-01 (commit 9f3da78); v1 folds in the operator's mount
decisions, the `~/ai-os/notes` merge, and live checks made the same day.

## TL;DR

Ship Corral Light as **one multi-arch OCI image** (linux/amd64 + linux/arm64)
carrying pinned Python, Node, both npm adapters, the four agent CLIs, and a
pinned copy of AI-OS Seed. A host needs only a container runtime and a
~40-line POSIX `corral` shim. One `compose.yaml` replaces the launchd plist,
the systemd units, `install_service.py`, the `spike/ npm install` step, and
the second clone of Seed.

Agents see **`~/aios` and `~/notes` by default** (the `aios` scope). A `home`
scope mounts all of `~` for power seats, with container-only volumes shadowing
the Mac binaries that live there.

**The catch, stated first:** a contained agent reaches only files. The macOS
Keychain (and so the secret broker), launchctl, brew, osascript, desktop
notifications and USB serial stay out of reach on a Mac in either scope.
So the container is the default for every new host and every non-the operator user;
The Mac host's daily seat keeps the native checkout as "dev mode" until Phase 3.

## What is messy today (measured 2026-10-01)

| Pain | Evidence |
|---|---|
| Python drift | No pin. Hub floor 3.9 (`hub.py:44`); the Mac host runs brew 3.14; Seed scripts need 3.10+. |
| Two service formats | launchd plist + systemd unit + watch service/timer, generated by `install_service.py`. |
| Hidden setup step | `spike/node_modules` is gitignored; `doctor.py` exists largely to explain the missing `npm install`. Needs Node on host. |
| Per-platform binaries everywhere | `spike/node_modules` holds `codex-darwin-arm64` and `claude-agent-sdk-darwin-arm64`; Grok is `~/.grok/downloads/grok-1.0.46-macos-aarch64`; Antigravity is a per-platform build. |
| Two repos, two clones | README: install Seed into `~/aios`, then clone Corral Light. Versions are not pinned to each other. |
| Workspace path mismatch | README and `sessions.py:410` assume `~/aios`; on the Mac host the workspace is `~/ai-os`. |
| Lane defaults lag | Live 2026-10-01: Grok lane defaults to grok-4.6 (4.7 exists), Codex to effort `low`, Gemini to 3.7 (3.8 exists). |

## The shape

```
host                                   container  ghcr.io/cvp1/corral-light:<ver>
────                                   ─────────────────────────────────────────
corral (POSIX sh shim) ─ compose ────▶ hub.py  (Python 3.12, base pinned by digest)
                                       spike/node_modules (baked, linux builds)
                                       claude, codex-acp, grok, antigravity (linux builds)
                                       /opt/aios-seed  (Seed @ pinned tag, own venv)
127.0.0.1:8098  ◀── port publish ───── :8098
Ollama (native, GPU) ◀─ host.docker.internal:11434
$CORRAL_WORKSPACE ─ bind, same path ─▶ same path       (default ~/aios)
~/notes        ── bind, same path ───▶ ~/notes          (second brain)
volume corral-state ────────────────▶ ~/.local/share/corral-light
volume corral-home  ────────────────▶ ~/.codex ~/.gemini ~/.grok (logins, linux binaries)
```

Decisions inside that picture:

- **Same absolute paths inside and out.** Mounts land at the host's own paths
  and the container's `$HOME` equals the host's, so transcripts, attach-file
  paths and agent output read identically on both sides.
- **Host UID.** Compose runs as `${UID}:${GID}` so files written into bind
  mounts are owned by the user on Linux. Docker Desktop maps this on macOS.
- **Pinned hostname.** Compose sets `hostname:` to the host's own name. Inside
  a container `hostname` is otherwise the container ID, and fleet doctrine
  (single-writer rule, "believe hostname") keys on it.
- **Loopback only.** Publish `127.0.0.1:8098:8098`. The pairing gate and
  WebAuthn origin stay exactly as today.
- **Ollama stays native.** Containers on macOS get no Metal GPU. Point the
  existing `CORRAL_OLLAMA_URL` at `host.docker.internal` (Linux adds
  `extra_hosts: host-gateway`).
- **Restart policy replaces launchd/systemd.** `restart: unless-stopped` plus
  a compose healthcheck. `install_service.py` and the unit templates retire
  for container installs.

## Mount scopes

One setting, `CORRAL_SCOPE`, picks what agents can see.

| Scope | Mounts | For |
|---|---|---|
| `aios` (default) | `$CORRAL_WORKSPACE` and `~/notes`, plus paths named in `CORRAL_EXTRA_MOUNTS` | Novices, new hosts. The sandbox is the product. |
| `home` | all of `~`, plus the shadow volumes below | Power seats. Native reach for anything that is a file. |

On the Mac host, `aios` scope is `~/ai-os` + `~/notes` with `~/Github` as the one
extra. (`~/ai-os/notes` was merged into `~/notes` and retired on 2026-10-01,
so there is one notes folder.)

### `~/notes` rules (the operator, 2026-10-01: "the second brain is there")

- **Create it before mounting.** `install.sh` creates `~/notes` as the user if
  missing; Docker on Linux would otherwise create a root-owned folder.
- **Writes leave the machine.** On the fleet `~/notes` is Syncthing-synced, so
  a container agent's write reaches every host. Host UID keeps ownership right.

### Hooks must never fail open — in EITHER scope

Every hook in the workspace's `.claude/settings.json` calls
`~/.venvs/aios-seed/bin/python3` by absolute path, and on the Mac host that file is
a Mach-O binary. Inside a Linux container:

- in `aios` scope the path is not mounted at all, and
- in `home` scope it is mounted but cannot execute.

Either way the hooks fail to run, and a failing PreToolUse hook does not block
— so the memory-mesh write guard **fails open silently**. This is the most
serious risk in the plan. Fixes, all three required:

1. The entrypoint provides a Linux interpreter at the exact path the hooks
   name: in `aios` scope a symlink to `/opt/aios-seed/venv`, in `home` scope a
   container volume shadowing `~/.venvs/aios-seed`.
2. `doctor` (and the healthcheck) executes every configured hook once with a
   no-op payload and **refuses to start the hub** if any hook cannot execute.
3. Longer term, Seed writes hooks against a portable launcher
   (`$WORKSPACE/bin/py`) instead of an absolute venv path.

### `home` scope: shadow the Mac binaries

Container-only volumes mounted over these paths, at the same paths, holding
Linux builds — the host copies are untouched:

- `~/.local/bin` (holds Mach-O `claude`)
- `~/.venvs/*` (Mach-O Python, see above)
- `~/.grok/bin` and `~/.grok/downloads` (Mach-O Grok CLI)
- `~/.gemini/antigravity-acp` and `~/.local/lib/corral` (per-platform Antigravity)
- any `node_modules` the hub runs from

`doctor` lists symlinks inside the mounted set that point outside it; they
dangle in the container.

**`home` still cannot give back** anything that is a service rather than a
file: the Keychain, launchctl, brew, osascript, notifications, USB serial on
macOS. On a Linux host, `home` is close to full parity.

### Logins

- **Claude:** on macOS the CLI keeps credentials in the Keychain, which a
  Linux container cannot read. The container gets `CLAUDE_CODE_OAUTH_TOKEN`
  injected at start, read from the fscrypt vault at point of use
  (`~/.key/claude_code_oauth_token.key` exists on the Mac host), so no credential
  file is written into `~`. A host without a vault token runs
  `corral login claude` once (`claude_login.py` exists) and the result lives
  in `corral-home`, never in the host's `~/.claude`.
- **Codex, Grok, Gemini:** one-time login per host into `corral-home`.
- **gh and ssh from Linux:** unverified [NEEDS VERIFICATION]; both can depend
  on the Keychain on macOS.

## Seed: bundled, not cloned

- The image carries Seed at a pinned tag in `/opt/aios-seed` with its own
  venv. One Corral Light release pins one Seed release; CI tests the pair.
- `corral init` runs Seed's `install.py --target <workspace>` from inside the
  image when the workspace is empty, or `--into` an existing one.
  `corral update` pulls the new image, then runs `install.py --update`.
  No second clone on any host.
- **Seed's scheduler stays host-native.** It reconciles launchd/systemd by
  design and its jobs touch the host. That is the one place a host still
  needs Python; `uv` with `.python-version` 3.12 removes the version guessing.
- `CORRAL_WORKSPACE` (default `~/aios`) drives both the mount and
  `sessions.py`'s default directory, fixing the `~/aios` vs `~/ai-os` miss.

## Install, as a user sees it

```
curl -fsSL https://<release-url>/install.sh | sh   # writes ~/.config/corral-light/compose.yaml, pulls, starts
corral pair ABC-123                                 # docker exec under the hood
corral login claude                                 # once per host, unless a vault token exists
corral doctor
```

Same four lines on macOS and Linux. `install.sh` is short, readable and
checksummed in the release; it never pipes a second download into a shell.

## Keeping lanes current

- In container mode an adapter bump is an image rebuild, not an on-host swap.
- Scheduled CI runs `lanes check`; on `behind` it builds a candidate image,
  runs the `selftest_*.mjs` suite, `doctor`, and one real prompt per lane
  inside it, and only then tags. Same "proven before anything moves" contract
  as `lanes update`, moved off the host.
- `lanes update` stays for dev mode.
- **Lane defaults follow the newest model.** The image's seeded config pins
  each lane's default model and effort to the newest available at build time,
  so a consult that forgets `--model` does not silently land on an old model.

## Dev mode (the Mac host today)

`compose.dev.yaml` bind-mounts the checkout over `/app` (with a container
volume over `spike/node_modules`) so edits are live without a rebuild. The
native checkout + launchd path stays supported on the Mac host only until Phase 3.

## What we lose, honestly

1. **Service-level host reach** on macOS: Keychain secret broker, launchctl,
   brew, rigctl/IC-7300 serial, osascript, notifications. A sandbox for a new
   user; a regression for the operator's daily seat.
2. **A VM on macOS.** Docker Desktop (29.6.2, linux/arm64 on the Mac host) costs
   memory and must start at login for the hub to return after reboot.
3. **A second login per lane per host** where no vault token exists.
4. **`watch` from outside.** A sidecar can probe the hub but cannot raise a
   macOS notification; it needs a push channel.
